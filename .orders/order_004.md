# 追加指示：ガイダンス資料の取り込み／当面GitHub Pages上でデバッグする方針への切り替え

対象リポジトリ：https://github.com/yryo1005/SIT-AIRD-Center-Homepage

## 0. 今回の位置づけ

これまで「PDF/PPTXなどのアップロードファイルからの情報・画像抽出」は指示書でスコープ外としてきましたが、今回`references/`ディレクトリにガイダンス資料等をアップロードしたため、このフェーズに着手します。あわせて、ArtisCMS3への実際の組み込み作業は一旦保留し、確認・デバッグはGitHub Pages上で直接行う方針に切り替えます。

## 1. 当面の確認方法の変更

- ArtisCMS3の埋め込みHTML欄への`cms-shells/`の貼り付け作業は、今回は行わない（後回しにする）。この指示のスコープには含めない
- 動作確認は、GitHub Pagesで公開されている各ページのURL（`https://yryo1005.github.io/SIT-AIRD-Center-Homepage/src/pages/<ページ名>/index.html`）に直接ブラウザでアクセスして行う
- iframe埋め込み関連の実装（`target="_top"`、高さ自動調整のpostMessage処理など）はそのまま残してよい。単体ページとして開いても壊れないことだけ確認できていれば十分で、今回iframe越しの動作確認は不要

## 2. `references/`配下のガイダンス資料の取り込み

### 2.1 対象ファイルの確認

`references/`ディレクトリの中身（PDF、PPTXなど）をすべて確認し、ファイルごとに種類・ページ数（PPTXならスライド数）・概要を一覧化して、まず提示すること。実際の編集作業に入る前に、こちらで内容を確認できるようにする

### 2.2 内容の抽出方針

- PDFはそのまま読み込み、テキスト・図表・画像を把握する
- PPTXは、必要に応じてスクリプトを書いて（unzip＋XML解析、または`python-pptx`等を用いて）テキストと`ppt/media/`配下の埋め込み画像（元画質）の両方を抽出する。スライド全体をレンダリングして見た目を確認する作業と、写真素材を劣化なく取り出す作業は別工程として扱うこと
- 抽出した内容のうち、サイトへの反映候補となる文章・画像を整理して提示すること（全部を無条件に反映するのではなく、内容の重複・重要度を踏まえて候補を出す）

### 2.3 サイトへの反映ルール（厳守）

- **公式サイト（`.orders/order_001.md`で指定した参照元）にすでに存在する情報を、ガイダンス資料の内容で削除・上書きしないこと。** 追加・補強のみを行う
- ガイダンス資料の内容が公式サイトの内容と食い違う場合（数値や事実関係が異なる等）は、独断でどちらかを正しいと判断して書き換えず、食い違いの内容を明示して報告すること
- ガイダンス資料に無い情報を推測で補って書き足さないこと（これまでの「事実を捏造しない」方針を継続する）

### 2.4 画像の扱い

- ガイダンス資料から抽出した画像は、リポジトリ内（例：`src/assets/images/`等、Viteの通常のアセットパイプラインで扱える場所）に配置し、各ページから参照する
- GitHub Releaseなど外部ホスティングへの切り出しは、今回は行わなくてよい（必要になった場合は別途指示する）
- 画像ファイル名は内容が分かるように命名し、どのガイダンス資料のどの部分から抽出したものかをコミットメッセージまたはコメントで分かるようにしておくこと

## 3. 進め方

1. `references/`配下のファイル一覧と概要を提示する（2.1）
2. サイトへの反映候補（追加・補強できそうな文章・画像）を整理して提示し、こちらの確認を待つ
3. 確認後、該当ページに反映する
4. `npm run build`が通ることを確認し、GitHub Pages上の該当ページURLで実際に表示・画像表示を確認する
5. 変更内容をコミットし、pushする（Actionsが成功し、GitHub Pages上に反映されたことまで確認してから報告すること）
